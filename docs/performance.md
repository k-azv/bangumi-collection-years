# 性能验证

版本：0.3.6。环境：本机 Node.js、JSDOM；结果反映脚本处理开销，浏览器布局、绘制和网络延迟需单独采样。

## 请求与缓存

- 加载期间连续三次触发页面可见事件，共一次请求。
- 数据相同且缓存有效时保留图表节点与交互状态。
- 收藏状态独立失效；概览复用其余有效状态。
- 存储不可用或配额不足时使用页面内存缓存。
- 持久缓存保留最多 50 条记录，写入时清理超过七天的记录。

## 后续检查结论

1. 大收藏量下，缓存 JSON 解析、条目校验和展示内容比较仍与收藏量成正比。五万条合成数据的页面返回处理达到约 71 ms，应优先考虑复用已解析缓存和数据版本。
2. `checkCurrentPage` 对当前页条目逐个遍历缓存查找，最坏复杂度为当前页条目数乘收藏总数；可以使用 subjectId 索引。
3. 持久缓存写入的清理流程解析各条记录，开销随已保存用户数及收藏量增长；独立元数据索引可以降低该成本。
4. 首次加载需逐页请求完整收藏 HTML，单状态串行分页；作品量大时首次等待主要取决于页数和站点响应。日期缺失条目还需读取详情页。
5. 图表节点数主要由年份跨度决定；收藏量增长本身不会增加已知年份图表的节点数。待确认条目列表则按条目数创建节点，极端情况下应考虑按需展开渲染。
